# Were the NYPD Violence Reduction Zones an efficient use of officers?

This repository holds the data, code, and figures behind a Vital City "Reality
Check" piece by Erik Alda, written as a companion to John Hall's analysis of the
NYPD zone strategy. The article asks a narrower question than whether crime fell:
were the officers used *efficiently*, that is, did each extra officer turn into
more safety than the same officer would have produced somewhere else, once the
drop that was coming anyway is taken out.

The short answer is that the public data can raise the question but cannot settle
it. The zone-era efficiency gain is mostly the citywide decline in crime. When
you compare the precincts a spike-based program would target against the rest in
the same years, so the citywide drop cancels, the edge roughly halves and is no
longer distinguishable from no difference. A check on an earlier decline shows
the same faint drift. The one comparison that would settle it, the actual zone
precincts against everywhere else, cannot be run from outside because the City
does not publish which precincts the zones cover.

## What "efficiency" means here

There is one input, the officers a precinct has (proxied by arrests, the only
deployment signal in the public data), and one output, the violence those
officers prevent. Crime enters as a reciprocal so that less crime counts as more
output (Lovell, Pastor & Turner 1995; the Färe–Grosskopf undesirable-output
tradition). Efficiency is measured with an output-oriented, variable-returns
(BCC) Data Envelopment Analysis frontier. Before scoring, each precinct's drop is
adjusted for **regression to the mean** ("the rebound"): a reversion model fit on
the no-zone era predicts how far a bad year would have fallen on its own, and the
zones are credited only with the drop beyond that.

## How to reproduce

All scripts run **from the repository root**.

Python:

```bash
pip install numpy pandas scipy matplotlib
python python/02_analyze.py        # build the panel + RTM netting + DEA
python python/10_reciprocal.py     # primary efficiency model (reciprocal, VRS)
python python/13_event_study.py    # parallel-trends diagnostic behind the DiD
python python/07_verify.py         # internal checks (primal=dual, CRS/VRS, netting)
python python/06_figures.py        # figures 1-3
python python/09_maps.py           # figure 4 (precinct maps)
```

R (run from the repository root):

```bash
Rscript R/install.R                # one-time: data.table, lpSolve, sandwich, lmtest, Benchmarking, ...
Rscript R/run_all.R                # builds the panel, reconciles every shared number, redraws figures
Rscript R/validate_benchmarking.R  # confirms the hand-coded LP equals Benchmarking::dea
```

The Python and R results agree. `R/validate_benchmarking.R` confirms the
hand-written linear program equals the field-standard `Benchmarking::dea`
(output-oriented VRS) to within 7e-7 on the 2025 cross-section, so the solver is
correct and not merely internally consistent.

## A note on what was dropped

An earlier directional-distance (DDF) model was removed. It is not
units-invariant and, as built, used the crime level rather than the rebound-netted
output, so it did not net the rebound cleanly. The reciprocal output-oriented
model replaces it. `python/legacy/` keeps the DDF stub and two earlier
specifications for the record; they are not part of the current pipeline.

## Data

Source aggregates come from NYC Open Data: historic and year-to-date shooting
incidents, complaint records (murder, rape, robbery; outdoor), and arrests,
summed to precinct × summer (June–September), 2012–2025, 77 precincts. The pull
scripts (`python/01_pull.py`, `python/01b_arrests.py`, `python/arr_pull.py`) hit
the Socrata API; the built `data/panel.csv` is included so the analysis runs
without re-pulling.
